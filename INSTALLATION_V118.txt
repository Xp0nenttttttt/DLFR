DLFR V118 — CATALOGUE DLFR CARDS DANS SUPABASE (création / suppression de cartes et collections)
==============================================================================================
BASE : V117 installée.

SQL : DÉJÀ APPLIQUÉ sur le projet Supabase « DLFR » (migration dlfr_118_cards_catalogue).
  Copie de référence : supabase/118_DLFR_CARDS_CATALOGUE.sql — NE PAS la relancer.

INSTALLATION GITHUB PAGES :
  1. Remplacer index.html.
  2. Remplacer js/app.js (une seule ligne ajoutée après la création du client Supabase :
     window.DLFR_CARDS_LAB?.setClient?.(db);  → si tu as modifié app.js depuis, ajoute juste cette ligne).
  3. Ajouter js/v118-cards-lab.js et css/v118-cards-lab.css.
  4. GARDER css/v116-cards-lab.css et css/v117-cards-lab.css (toujours chargés).
  5. Publier, puis Ctrl + F5.
js/v117-cards-lab.js peut rester dans le dépôt : il n'est plus chargé.

CE QUI A ÉTÉ AJOUTÉ DANS SUPABASE (uniquement des ajouts) :
  - Tables dlfr_card_collections et dlfr_cards (les 50 cartes ORIGINS en 4 collections, mêmes numéros).
  - Lecture réservée au compte autorisé du labo (dlfr_cards_lab_access = Spleen + owner).
  - Aucune écriture directe possible : tout passe par 4 fonctions qui vérifient l'accès :
      dlfr_cards_admin_save_collection / dlfr_cards_admin_delete_collection
      dlfr_cards_admin_save_card       / dlfr_cards_admin_delete_card
  - Espace d'images « dlfr-cards » : lecture publique, envoi/suppression réservés au compte autorisé,
    2 Mo max, PNG/JPEG/WebP/GIF.
  - Testé : Spleen peut lire/créer/modifier/supprimer ; un autre compte connecté ne voit rien et ne peut
    rien modifier ; un visiteur non connecté n'a aucun accès.

DANS LE LABO — nouvel onglet « ✎ Catalogue » :
  - Collections : créer (nom, nom court, description, couleur, ordre), modifier, supprimer.
    Supprimer une collection qui contient des cartes demande de retaper son nom court.
  - Cartes : créer, modifier (nom, catégorie, rareté, collection, description, image, ordre), déplacer
    vers une autre collection, supprimer. Aperçu en direct.
  - Image par URL https ou envoyée depuis le PC (stockée dans Supabase ; l'ancienne image est
    supprimée quand on la remplace ou qu'on supprime la carte).
  - Case « Peut sortir dans les boosters » : décocher pour une carte réservée (récompense, événement…).
  - Importer des cartes (JSON) dans une collection : fichiers de créations V113, sessions V114–V117,
    ou sauvegarde de catalogue. Les images base64 sont envoyées dans Supabase.
  - « Sauvegarde JSON » : export complet du catalogue.
  - Album : filtre par collection + bouton « Modifier dans le catalogue ».
  - Les boosters, expéditions, séries et succès utilisent automatiquement le catalogue Supabase.
    Une série « collection » est créée pour chaque collection.

À SAVOIR :
  - Le catalogue est enregistré pour de vrai ; la progression du labo (cartes possédées, niveaux…)
    reste un essai en mémoire, comme avant (export/import de session toujours disponible).
  - L'ancien onglet « Créer des cartes » local a été remplacé par le Catalogue.
  - Si Supabase est injoignable, le labo affiche le catalogue intégré (50 cartes) en lecture seule.
  - Les numéros des nouvelles cartes commencent à 1001 ; un numéro supprimé n'est pas réutilisé.
  - Pour ouvrir plus tard le catalogue aux joueurs, il suffira d'élargir la règle de lecture des deux
    tables (prochaine étape avec les inventaires côté serveur).
