# DemonlistFrancophone V1.2 — Guide simple

Cette V1.2 reprend le projet DLFR (HTML/CSS/JS/Supabase) transmis dans la conversation. **Aucun SQL n'est nécessaire pour tester ses nouveautés en démonstration.** Le site PHP historique n'est pas modifié.

## Démarrer en 1 minute

1. Dézipper l'archive complète. Ouvrir `index.html` avec Chrome/Opera ou publier les fichiers sur GitHub Pages.
2. Si le projet est déjà connecté à un Supabase vide, accéder à `index.html?demo=1` (en local) ou ajouter `?demo=1` à l'URL GitHub Pages. Le bouton « Voir le site avec des données d'exemple » fonctionne également.
3. Tester **Statistiques → Joueurs / Pays / Comparaison**, puis les onglets **Présentation / Records / Graphiques / Distinctions** d'un joueur.
4. Tester **Actualités** : catégories, recherche, annonce à la une, images et vidéos.
5. Ouvrir **Modération → Activer la simulation modérateur**, puis utiliser les rubriques de gauche. Publier, éditer ou passer une actualité en brouillon, modifier un profil, attribuer un titre ou ajouter un niveau.
6. La démo conserve les changements dans le stockage local du navigateur. **Exporter la démo** produit un JSON de sauvegarde ; **Importer une démo** restaure une sauvegarde. « Réinitialiser démo » revient aux exemples de base.

## Mettre à jour un dépôt GitHub V1.1

Le mini-patch contient exactement trois fichiers à remplacer :

- `js/app.js`
- `js/demo-data.js`
- `css/style.css`

Conserver **`js/config.js`**, car il peut contenir les références de ton projet Supabase.

Faire un commit sur `main`, attendre la publication GitHub Pages, puis faire Ctrl+F5. Pour tester sans SQL, ouvrir `https://TON-PSEUDO.github.io/DLFR/?demo=1`.

## Nouveautés

- **Profils :** pages détaillées, onglets Présentation/Records/Graphiques/Distinctions, historique points + rang, archives par année, dernières complétions.
- **Statistiques :** compteurs globaux, classement par pays, comparaison de deux joueurs, filtres par année.
- **Actualités :** recherches, catégories, publications épinglées, aperçu de publication, édition et passage en brouillon, médias préexistants conservés.
- **Modération :** tableau de bord, navigation par domaines, formulaires réorganisés, profil pré-rempli selon le joueur choisi, JSON import/export et journal local.
- **Design :** ajustements Pointercrate, meilleur responsive, thème sombre, prise en charge de la navigation au clavier.

## Ce qui ne touche PAS Supabase

Tous les exemples affichés en mode démo (`?demo=1`) sont fictifs et restent sur l'appareil. Il est impossible d'administrer Supabase avec l'option « Activer la simulation modérateur ».

Les **catégories et épinglages d'actualités** sont enregistrés **uniquement en mode démo** pour l'instant. En mode Supabase réel, l'interface peut classer les annonces par analyse du titre, mais ces nouveaux champs ne sont pas envoyés à la base tant qu'on n'a pas préparé une migration SQL. Les autres champs existants (texte/image/vidéo, publication) utilisent les tables et les droits RLS déjà présents, sous réserve que le projet soit correctement installé.

Le classement par pays s'appuie sur les pays et les points affichés localement, sans inventer de statistiques historiques. Les graphiques d'historique de points/rangs utilisent des exemples pour la démo ; sur un vrai site, ils attendent les instantanés réels.

## Protection

Ne jamais publier une clé `service_role`, une clé `secret`, un fichier d'identifiants MySQL ni les données privées des comptes sur GitHub. Seule une clé **Supabase publishable/anon** avec des politiques RLS adaptées doit être utilisée dans le navigateur.

Les modifications de la V1.2 doivent être testées en mode démo avant connexion à la base de production. Aucune migration SQL V1.2 n'est fournie : cette version est centrée sur le frontend.
