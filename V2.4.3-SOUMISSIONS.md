# DLFR V2.4.3 — Soumissions et validation de niveaux

## Ce qui existait dans la V2.4.2
La page Modération permettait l'ajout manuel d'un niveau, avec une case UNRATED. Elle ne comportait **pas** de file d'attente de soumissions et n'acceptait pas automatiquement un record sur un nouveau niveau.

## Ce qui est ajouté en V2.4.3 (démonstration uniquement)
1. Ouvrir `?page=submit-record&demo=1`, ou cliquer sur **Soumettre**. Entrer un nom de niveau, un joueur, une progression et un lien vidéo.
2. Ouvrir `?page=admin&demo=1` et **Activer la simulation modérateur**.
3. Dans **Niveaux**, trouver la soumission dans **Soumissions de records à examiner**.
4. Si le niveau existe (ID Geometry Dash prioritaire, nom sinon), seul le record est accepté : le statut Rated/UNRATED du niveau ne change pas.
5. Si le niveau n'existe pas, choisir obligatoirement **Rated** ou **UNRATED** et indiquer sa position.
   - **Rated** : insertion dans le classement global (et décalage des positions des niveaux Rated suivants). Si le #150 passe #151, il devient Legacy.
   - **UNRATED** : insertion dans le classement **alternatif**, à la position estimée renseignée. Le classement officiel Rated reste intact.
6. Accepter ou refuser. Les choix sont conservés localement dans le navigateur via `localStorage`. Le bouton Réinitialiser démo les efface.

Une soumission fictive « DÉMO — Nebula Labyrinth » permet d'essayer immédiatement la validation. Choisir par exemple **UNRATED** au rang estimé #29, puis activer le mode UNRATED pour voir le résultat. L'essai n'affecte pas Supabase.

## Sécurité et future migration Supabase
**Aucune acceptation réelle n'est activée sur le site connecté à Supabase.** L'écriture de soumissions, le choix du type, l'insertion de niveaux et la mise à jour des positions doivent passer par une **transaction sécurisée côté serveur** (PostgreSQL via RPC/Edge Function), avec authentification, contrôle des rôles, prévention des doublons et journal d'audit. Ne jamais faire confiance aux boutons « modérateur » ou au choix Rated/UNRATED du navigateur pour attribuer des permissions. Les points et historiques officiels doivent être recalculés après migration à partir des données réelles.

## Installation GitHub
Décompresser le patch dans le dépôt en conservant l'arborescence :
- `index.html`
- `css/style.css`
- `js/app.js`
- `js/demo-data.js`
- `js/submission-core.js` (nouveau)

Le patch ne contient **aucun drapeau** : tes PNG dans `assets/flags/` restent inchangés. Ne remplace pas `js/config.js`.

Tester avec `?page=submit-record&demo=1`. Si une ancienne session de démo garde des données incohérentes, exporter la démo depuis Modération, puis utiliser `&reset=1` (cela réinitialise uniquement la démo locale).
